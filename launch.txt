Mushroom Island Search — Windows launch instructions

The current gpt branch is the O6 translation pipeline. The first GPU tier
uses O6 only at 1x step 250 and threshold -0.46. Each connected component
meeting the 6M area gate emits one representative hit, which is translated across
the world border and screened on the GPU with O6+O15 threshold -0.88 at
250-block spacing and R=2, then sent to the CPU. The CPU first runs a native
six-octave 1x connected-grid validation at 250-block spacing; only validation
passes enter the six-octave flood and then the full flood. Grouped mode keeps
translation enumeration on the GPU and reuses each seed's permutation tables
across all translations.

1. Open an SSH shell or a Developer Command Prompt on Windows.

2. Fetch and merge the current branch. Run this from the repository root.
   This preserves any local Windows commits:

    cd /d D:\Code\Seeds
    powershell -NoProfile -ExecutionPolicy Bypass -Command "$vpn = Get-Content .\VPN.txt -Raw; Invoke-Expression $vpn; git fetch origin gpt"
    git switch gpt
    git merge --no-edit origin/gpt

3. Build the GPU DLL. Use a fresh shell before calling vcvars64.bat:

    cd /d D:\Code\Seeds
    gcc -O3 -shared -o engine\continentalness.dll engine\continentalness.c -Iengine -lm
    call "C:\Program Files\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat"
    nvcc -O3 -arch=sm_120 -Xptxas=-v,-warn-spills,-warn-lmem-usage -shared -o gpu\hunt_engine.dll gpu\hunt_engine.cu gpu\tiered_kernel.cu gpu\coarse_verify_kernel.cu gpu\prefilter_kernel.cu engine\continentalness.c -Iengine -lcudart

4. Run a bounded production test. This processes one prefilter batch and
   writes final islands to gpu\islands_6m.jsonl:

    cd /d D:\Code\Seeds
    set HUNT_O6_THRESHOLD=-0.46
    set HUNT_O6_STEP=500
    rem HUNT_O6_STEP is the 2x reference; the GPU first tier derives 1x=250.
    set HUNT_PREF_BATCH=100000
    set HUNT_SCAN_LIMIT=16
    set HUNT_TRANSLATION_PERIOD=131072
    set HUNT_WORLD_BORDER_PIPELINE=7500000
    set HUNT_TRANSLATION_ESTIMATE_STEP=250
    set HUNT_TRANSLATION_ESTIMATE_STEP_2X=500
    set HUNT_TRANSLATION_ESTIMATE_THRESHOLD=-0.88
    set HUNT_TRANSLATION_ESTIMATE_TARGET=6000000
    set HUNT_TRANSLATION_GROUPED=1
    set HUNT_TRANSLATION_GROUPED_THREADS=256
    set HUNT_CPU_VALIDATION_STEP_1X=250
    set HUNT_CPU_VALIDATION_STEP_2X=500
    set HUNT_CPU_VALIDATION_THRESHOLD=-1.0
    set HUNT_CPU_VALIDATION_TARGET=6000000
    set HUNT_CPU_6OCT_GATE=6000000
    set HUNT_TARGET_AREA=6000000
    set HUNT_CPU_WORKERS=28
    set HUNT_OUTPUT_FILE=gpu\islands_6m.jsonl
    set HUNT_BEST_FILE=gpu\best_6m.jsonl
    set HUNT_MAX_PREFILTER_BATCHES=1
    set HUNT_DEBUG_TRANSLATION_STATS=1
    set HUNT_PROFILE_STAGES=1
    python gpu\hunt_tiered.py

   Remove HUNT_MAX_PREFILTER_BATCHES for an indefinite search. Use
   HUNT_START_SEED=0x123456789ABCDEF0 for a deterministic test start. Remove
   HUNT_SCAN_LIMIT after the bounded test to scan every prefilter survivor.

   For a deterministic GPU-only A/B benchmark, keep the same environment and
   run:

    set HUNT_PREF_BATCH=500000000
    set HUNT_SCAN_LIMIT=1600
    set HUNT_THRESHOLD=-0.46
    set HUNT_DEBUG_TRANSLATION_STATS=1
    set HUNT_TRANSLATION_GROUPED=1
    set HUNT_TRANSLATION_GROUPED_THREADS=256
    python gpu\benchmark_translated.py

   Repeat with HUNT_TRANSLATION_GROUPED=0 for the expanded one-block-per-
   translation baseline. The sorted SHA-256 values must match.

5. Inspect outputs:

    type gpu\islands_6m.jsonl
    type gpu\best_6m.jsonl

6. Build and run the standalone CPU translation sweep. This is separate
   from the new GPU O6-only production pipeline. It logs each translated
   island >=5M immediately, including the original island area:

    cd /d D:\Code\Seeds
    cl /O2 /EHsc /std:c++17 gpu\o6_translation.cpp engine\continentalness.c /Fe:gpu\o6_translation.exe
    gpu\o6_translation.exe gpu\islands_4m.jsonl gpu\o6_translation_larger_5m_checkpoint.csv 28 -0.95 5000000

   The sweep output is checkpointed after each completed source record.
   Stop it with Ctrl+C; the existing CSV remains usable. Re-running the
   command starts a fresh CSV rather than resuming the previous run.
